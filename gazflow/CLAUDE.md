# GazFlow · מכונת היום — Claude Code Instructions

## 📌 Project Overview
An interactive, Hebrew (RTL) spatial presentation of the operating logic for an
Israeli home LPG-cylinder delivery business: one 3D diorama (react-three-fiber)
that morphs through 9 chapters, plus a 2D schematic mode and an editorial HUD.

It was originally scaffolded with Grok App Builder and has been migrated to
Claude Code for refactoring, auditing, performance optimization, and active
development. The Grok-only PWA/OG head injection, brand-check, and preview
harness were removed during migration; some Grok scaffolding remains and is
currently unused by the app (see "Dormant scaffolding").

**Stack:** React 19 · TanStack Start/Router · Vite 8 · Three.js via
`@react-three/fiber` + `drei` · Tailwind CSS 4 · Nitro (Vercel preset) ·
TypeScript (strict). Node 22.

## 🚚 The operations app (the product we deliver)
A gas distributor's whole day, with the owner only watching. Three people, three secret links, no passwords:
- `/c/<token>` — **customer** (Arabic/Hebrew): three big buttons — order like last time, call (logged, so the office sees who is about to ring), where is my order — plus cylinders at home, debt, history.
- `/d/<token>` — **driver**: today's stops in route order; on the way → delivered (quantity, empties, cash/debt/transfer) or not delivered (reason).
- `/o/<token>` — **office**: "needs you" (call taps, held orders, transfers to confirm), driver progress, all of today's orders, who needs gas this week; customers, drivers, settings.

Automation (no human needed): an order is assigned to the least-loaded driver serving its zone; orders after the cutoff hour go to tomorrow; high debt, unknown zone, no driver or full trucks hold the order for the office; a failed stop goes to the end of the route, a second failure moves it to tomorrow and flags the office; unfinished stops carry over each morning; refill is due two days before each customer's measured cycle ends.

- `src/lib/ops/logic.ts` — every business rule as a pure function (tested in `logic.test.ts`). Change rules here first.
- `src/lib/ops/service.server.ts` — the rules wired to SQL; every entry point resolves the caller's token first. Multi-row changes go through `withTransaction` (`src/lib/db.ts`).
- `src/lib/ops/api.ts` — validated `createServerFn` endpoints (zod); `src/lib/ops/i18n.ts` — all Arabic/Hebrew strings.
- `src/components/ops/` — `CustomerApp`, `DriverApp`, `OfficeApp`, shared `kit.tsx` / `hooks.ts`. Light theme (`paper`/`ink`, Rubik for Arabic + Hebrew), big touch targets.
- `migrations/0002_ops.sql` — schema. New changes go in new numbered files.
- **Preview / dev** (no `DATABASE_URL`): in-memory PGlite with demo data — `/o/demo-owner`, `/c/demo-c1`…`demo-c6`, `/d/demo-d1`, `/d/demo-d2`. Demo prices are 0 until set in office settings.
- `e2e/ops.e2e.mjs` — the full day as browser tests (names in Hebrew). Run `npm run e2e` before every change that touches ops; add a test for every new flow. `OPS_FIXED_NOW` pins the clock, and only in preview.
- **Production:** set `DATABASE_URL` (Postgres) and `OWNER_TOKEN` (a long random string — it is the office password). The office link is logged at first start. No demo data is created.

## 🗺️ Where things live
- `src/routes/__root.tsx` — document shell, `<head>` meta (title, OG, fonts), `lang="he" dir="rtl"`.
- `src/routes/index.tsx` → `src/components/stage/Presentation.tsx` — the app.
- `src/components/stage/` — `StageCanvas` (R3F canvas), `World` + `meshes` (3D scene), `Schematic2D` (2D mode), `Hud`, `BriefPanel`.
- `src/lib/presentation/chapters.ts` — **all chapter content** (Hebrew copy, chips, camera poses). Edit copy here.
- `src/lib/presentation/palette.ts` — color tokens; `claude-brief.ts` — the creative brief shown in the BriefPanel. The brief is an internal tool: its button only appears with `?internal` in the URL.
- `src/routes/pitch.tsx` → `src/components/pitch/PitchPlayer.tsx` — the investor pitch film (`/pitch`): one continuous camera move through the same `World`. Scenes, shots and captions live in `src/lib/presentation/pitch.ts`; undecided figures stay `X`. `?scene=N` starts at a scene; `?record` stops the clock for `scripts/capture-pitch.mjs`, which renders frame-exact JPEGs for ffmpeg.
- `World` takes a `beat` (a chapter id, or the pitch-only states `hook`, `before`, `market`) and a camera pose; it does not know about chapters.
- `src/styles.css` — Tailwind theme (`bg-void`, `text-cream`, …).
- `artifacts/` — standalone business documents (price quote, system-logic doc) as HTML + PDF. Not part of the app build.
- `src/routeTree.gen.ts` — generated by the TanStack router plugin; never edit by hand.

### Content rules (keep the three documents consistent)
The presentation, `artifacts/logika-maarechet-gazflow.*` (logic spec) and `artifacts/hatzaat-mehir-gazflow.*` (price quote) must say the same thing.
- Chapters describe **package B** behavior (the recommended start). Anything only package C delivers goes in the chapter's `upgrade` field, which renders a "חבילה C" tag — never in the main line or chips.
- Inventory: warehouse and truck are physical stock; the reserve is an accounting lock on open orders, drawn on the warehouse — not a third pile. Available = warehouse + truck stock not yet out − reserve not yet loaded.
- Card clearing is "not at this stage", not "never" (the quote sells it as an add-on).
- When chapter copy changes, update `claude-brief.ts` to match.

### Dormant scaffolding (kept, not used by the presentation)
`src/lib/auth/*` + `migrations/auth` (better-auth, disabled via
`VITE_AUTH_ENABLED=false` in `.grok/app-env.json`), `src/lib/db.ts` (PGlite /
Postgres), `src/lib/app-data/*` (Grok connector gateway),
`src/lib/multiplayer/*`, and `preview-host-bridge` (no-op outside a Grok
iframe). Don't build on these without first deciding whether to keep them;
removing them is a pending cleanup.

## 👥 Engineering Team Architecture
Act as a cohesive, top-tier engineering team. Review every change through these roles:

1. **🏗️ Lead Software Architect** — structure, modularity, dependencies, scalability. Keep code clean, maintainable, strictly typed.
2. **🔍 Code Auditor & Debugger** — logic errors, edge cases, security, Grok-migration leftovers. Inspect modified code line by line before finishing.
3. **⚡ Performance & Refactoring Expert** — memory leaks (dispose Three.js geometries/materials, avoid per-frame allocations in `useFrame`), bundle size, async efficiency. Prefer pure, reusable functions.
4. **🎨 UI/UX & Frontend Specialist** — visual consistency, responsiveness (desktop **and** ~390px mobile), accessibility, RTL correctness, the brief's art direction (void/navy/cream + one copper accent, Frank Ruhl Libre + Heebo).
5. **📋 Product & Integration QA Manager** — end-to-end behavior (keyboard/tap chapter navigation, 3D↔2D toggle, brief panel), no regressions, concise changelogs.
6. **🎭 Creative Director & Pitch Specialist** — narrative, slide architecture, copy and market positioning for decks and client-facing presentations, at top-agency standard (Ogilvy / WPP level). Rules in "Pitch & Creative Protocol" below.
7. **🎥 Chief Motion Director & 3D Interactive Producer** — animated, real-time 3D pitch experiences: camera choreography, motion design, kinetic type, render/AI-video prompts (studio standard: Buck, Pentagram). Rules in "Motion-first pitches" below.

## 🚀 Pitch & Creative Protocol

### Know the audience first
Two different decks, two different arcs. Ask which one before writing.
- **Client sale** (what GazFlow is today: the presentation + quote sell a system to a gas-delivery business owner). Arc: today's pain (orders by phone, routes in someone's head) → the villain (memory, WhatsApp chaos, no stock truth) → the hero (the day machine) → *their* ROI, not TAM → packages A/B/C → pilot on one area → the ask: pick a package and sign.
- **Investor pitch**: Hook / pain → Villain → Hero (unfair advantage) → Market (TAM/SAM/SOM) → Business model & unit economics → Secret sauce / traction → The ask & ROI (amount, milestones).

### Evidence over adjectives
- No unbacked buzzwords ("revolutionary", "game-changing", "next-gen"). Every claim carries a number or a mechanism.
- **Every number traces to a source**: the logic spec, the quote, or a cited external source. Never invent market sizes, traction or metrics. If a figure is missing, say so to the user and propose how to get it; do not fill it in.
- Numbers must agree across the deck, the quote and the presentation (see "Content rules").
- Confidence comes from precision, not from overstatement.

### Headlines are value hooks
Not "Market Size" but a claim with a number. Not "Features" but what changes in the customer's day. Existing chapter titles ("המסילה לא מדלגת.") are the house voice: short, declarative, Hebrew.

### No plain bullet slides — deliver production storyboards
Each slide is specified as:
1. **Slide title** — the value hook.
2. **Visual layout** — exact composition (split, hero object, data cards, motion).
3. **Copy** — on-screen micro-copy with typographic hierarchy (kicker / title / one line / ≤3 chips).
4. **Presenter script** — what the founder says, executive register, ~20–40 seconds.
5. **Designer note** — concrete instructions for the build tool (this R3F app, Figma, Gamma, Midjourney…).

### Motion-first pitches (🎥 Chief Motion Director & 3D Interactive Producer)
The pitch is a **continuous 3D motion storyboard**, not a stack of static slides: one camera moving through one living scene, the way this app already works (one diorama, camera lerps per beat, scene morphs instead of remounting). Each scene is specified as:
1. **Scene title & narrative beat** — the hook this beat lands.
2. **3D layout & geometry** — what is in the scene and where (reuse the diorama: disc, warehouse, truck, houses, cylinder, rail, silos, pedestals, arc, clock).
3. **Animation & motion** — camera path (from/to pose, easing, duration), what morphs, kinetic typography, the transition into the next beat.
4. **Render / AI-video prompts** — ready-to-paste prompts (Runway, Luma, Midjourney, Spline) for any shot not rendered from this app, written in the house art direction.
5. **Voiceover & sync** — the script with the motion cue each line lands on.

Production stack, in order of preference: this R3F app itself (real-time, scroll/click driven) → Spline for one-off 3D shots → Lottie/Rive for UI micro-animations → AI video only for live-action or photoreal inserts. Motion must respect `prefers-reduced-motion` and hold 60 fps on a mid-range phone.

### Art direction for this project wins over generic examples
Void `#0e1419`, navy, cream, **one** copper accent `#c45c12`; Frank Ruhl Libre + Heebo; RTL Hebrew. No neon, no purple, no glassmorphism, no holographic HUDs, no emoji (see `claude-brief.ts`) — this also binds AI-video and render prompts. "If you add something, cut something else."

## 💻 Commands (run from `gazflow/`)
| Task | Command |
|---|---|
| Install | `npm ci` |
| Dev server (0.0.0.0:8080) | `npm run dev` |
| Production build (Vercel output in `.vercel/output`) | `npm run build` |
| Preview built app (127.0.0.1:8081) | `npm run preview` |
| Type check | `npx tsc --noEmit` (or `npm run typecheck`) |
| Lint | `npm run lint` |
| All tests | `npm test` |
| End-to-end (customer → office → driver, real browser) | `npm run e2e` — starts its own server on :8090 with fresh demo data and a clock pinned to 08:30 Israel time; screenshots in `e2e-results/` |
| One test file | `node --test scripts/<name>.test.mjs` or `node --experimental-strip-types --test src/<path>.test.ts` |

Tests use Node's built-in `node:test` runner — **not Jest**. A new `src/**/*.test.ts` file must also be added to the `test` script in `package.json`.

Visual check: there is no committed e2e suite. To verify UI changes, run the
dev server and screenshot with Playwright (installed as a devDependency;
Chromium at `/opt/pw-browsers/chromium` in Claude cloud sessions). WebGL
needs `--use-angle=swiftshader --enable-unsafe-swiftshader` headless.

## ⚙️ Execution Guidelines
1. **Pre-task inspection:** read the relevant source files before editing.
2. **Complete code:** no placeholders, TODOs, or partial snippets in active files.
3. **Verification after significant changes:** `npx tsc --noEmit`, `npm run lint`, `npm test`; for UI changes also `npm run build` and a browser screenshot at desktop and mobile widths.
4. **Self-correction:** if a check fails after your edits, read the error, fix it, and re-run until everything passes.
5. **Hebrew copy:** keep user-facing text in Hebrew, RTL-safe; don't machine-translate existing copy.
