# GazFlow · מכונת היום — Claude Code Instructions

## 📌 Project Overview
An interactive, Hebrew (RTL) spatial presentation of the operating logic for an
Israeli home LPG-cylinder delivery business: one 3D diorama (react-three-fiber)
that morphs through 9 chapters, plus a 2D schematic mode and an editorial HUD.

It was originally scaffolded with Grok App Builder and has been migrated to
Claude Code for refactoring, auditing, performance optimization, and active
development. The Grok-only PWA/OG head injection, brand-check, and preview
harness were removed during migration; some Grok scaffolding remains and is
currently unused by the app (see "Dormant scaffolding").

**Stack:** React 19 · TanStack Start/Router · Vite 8 · Three.js via
`@react-three/fiber` + `drei` · Tailwind CSS 4 · Nitro (Vercel preset) ·
TypeScript (strict). Node 22.

## 🗺️ Where things live
- `src/routes/__root.tsx` — document shell, `<head>` meta (title, OG, fonts), `lang="he" dir="rtl"`.
- `src/routes/index.tsx` → `src/components/stage/Presentation.tsx` — the app.
- `src/components/stage/` — `StageCanvas` (R3F canvas), `World` + `meshes` (3D scene), `Schematic2D` (2D mode), `Hud`, `BriefPanel`.
- `src/lib/presentation/chapters.ts` — **all chapter content** (Hebrew copy, chips, camera poses). Edit copy here.
- `src/lib/presentation/palette.ts` — color tokens; `claude-brief.ts` — the creative brief shown in the BriefPanel.
- `src/styles.css` — Tailwind theme (`bg-void`, `text-cream`, …).
- `artifacts/` — standalone business documents (price quote, system-logic doc) as HTML + PDF. Not part of the app build.
- `src/routeTree.gen.ts` — generated by the TanStack router plugin; never edit by hand.

### Dormant scaffolding (kept, not used by the presentation)
`src/lib/auth/*` + `migrations/auth` (better-auth, disabled via
`VITE_AUTH_ENABLED=false` in `.grok/app-env.json`), `src/lib/db.ts` (PGlite /
Postgres), `src/lib/app-data/*` (Grok connector gateway),
`src/lib/multiplayer/*`, and `preview-host-bridge` (no-op outside a Grok
iframe). Don't build on these without first deciding whether to keep them;
removing them is a pending cleanup.

## 👥 Engineering Team Architecture
Act as a cohesive, top-tier engineering team. Review every change through these roles:

1. **🏗️ Lead Software Architect** — structure, modularity, dependencies, scalability. Keep code clean, maintainable, strictly typed.
2. **🔍 Code Auditor & Debugger** — logic errors, edge cases, security, Grok-migration leftovers. Inspect modified code line by line before finishing.
3. **⚡ Performance & Refactoring Expert** — memory leaks (dispose Three.js geometries/materials, avoid per-frame allocations in `useFrame`), bundle size, async efficiency. Prefer pure, reusable functions.
4. **🎨 UI/UX & Frontend Specialist** — visual consistency, responsiveness (desktop **and** ~390px mobile), accessibility, RTL correctness, the brief's art direction (void/navy/cream + one copper accent, Frank Ruhl Libre + Heebo).
5. **📋 Product & Integration QA Manager** — end-to-end behavior (keyboard/tap chapter navigation, 3D↔2D toggle, brief panel), no regressions, concise changelogs.

## 💻 Commands (run from `gazflow/`)
| Task | Command |
|---|---|
| Install | `npm ci` |
| Dev server (0.0.0.0:8080) | `npm run dev` |
| Production build (Vercel output in `.vercel/output`) | `npm run build` |
| Preview built app (127.0.0.1:8081) | `npm run preview` |
| Type check | `npx tsc --noEmit` (or `npm run typecheck`) |
| Lint | `npm run lint` |
| All tests | `npm test` |
| One test file | `node --test scripts/<name>.test.mjs` or `node --experimental-strip-types --test src/<path>.test.ts` |

Tests use Node's built-in `node:test` runner — **not Jest**. A new `src/**/*.test.ts` file must also be added to the `test` script in `package.json`.

Visual check: there is no committed e2e suite. To verify UI changes, run the
dev server and screenshot with Playwright (installed as a devDependency;
Chromium at `/opt/pw-browsers/chromium` in Claude cloud sessions). WebGL
needs `--use-angle=swiftshader --enable-unsafe-swiftshader` headless.

## ⚙️ Execution Guidelines
1. **Pre-task inspection:** read the relevant source files before editing.
2. **Complete code:** no placeholders, TODOs, or partial snippets in active files.
3. **Verification after significant changes:** `npx tsc --noEmit`, `npm run lint`, `npm test`; for UI changes also `npm run build` and a browser screenshot at desktop and mobile widths.
4. **Self-correction:** if a check fails after your edits, read the error, fix it, and re-run until everything passes.
5. **Hebrew copy:** keep user-facing text in Hebrew, RTL-safe; don't machine-translate existing copy.
